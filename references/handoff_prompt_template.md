# 交接 prompt 模板

审阅结束后，作者常常会开一个新会话来执行修改。新会话不知道审阅时讨论过什么，所以 prompt 要把"依据、边界、环境、顺序、原则"都交代清楚。下面的结构来自一次实际的交接，按项目情况替换尖括号里的内容。保存为项目根目录下的 `prompt_apply_review_log_<日期>.md`。

```markdown
请根据审阅记录统一修改我的稿件。全程用<语言>和我交流。

## 任务
按 `<审阅记录路径>`（下称"审阅记录"）修改<期刊/学位论文>稿件及其补充材料，然后重新生成全部文件。审阅记录是唯一依据：

- 只执行状态为"已定"和"方向已定"的条目；"不改"的保持原样。
- 记录里给了草稿的，按草稿写；没有草稿的，按记录描述写。
- 审阅记录以外的任何改动，先问我，不要自行修改。
- 条目之间有冲突时，以较晚的决定为准，例如：<列出审阅中出现过的取代关系>。

动手前先完整读一遍审阅记录，向我复述你理解的修改范围，等我确认后再开始。

## 文件位置（项目根目录：`<路径>`）
- **稿件源文件**：<列出>
- **生成脚本**：<组装脚本、docx 生成脚本及其特殊约定，例如引用写法>
- **图**：<绘图脚本、输出目录、要沿用的已有图件或幻灯片脚本>
- **数据**：<源数据表、补算结果>
- **核对工具**：<数值核对脚本、引用核对脚本、文献关系分析文档>

## 运行环境（已验证可用）
<Python 路径与已装的包；pandoc、LaTeX 的路径和参数；已知的坑，例如某个程序在本机无法运行、某些字符会导致缺字>

## 执行顺序（每完成一个阶段，简要汇报一次）
1. 备份：<备份目录命名>
2. 参考文献：新增的先核对元数据再写入；删除的同步删除并重新编号
3. 正文：<按节列出主要改动>
4. 补充材料：<删减、重新编号>
5. 图：<新做、修改、删除；版式要求；每张新图都要看一遍渲染结果>
6. 重新生成：<顺序>
7. 检查：重跑数值核对，除审阅记录中指定的增删外，任何数值都不能改变；引用编号连续，没有未被引用的条目；图表按出现顺序引用；字数限制
8. 交付：把"方向已定"条目的改前改后对照写成一个文件；更新修订记录和 README；新建存档

## 必须守住的写作原则（详见审阅记录）
<把审阅中确定的措辞约束逐条写出来，例如某个结果只能写成"与……一致"、某个参数的定稿措辞、必须保留的结论边界句、术语和标点规范>
- 不新增审阅记录里没有的数据、结论或引用。

## 遇到以下情况先停下来问我
- 草稿中的数值与源数据对不上；
- 某处修改会影响审阅记录没有提到的内容；
- 重画的图和作者原有版式有明显差别。
```

## 写作要点

- **把审阅中踩过的环境问题写进去。** 例如某个工具的某个版本在本机不能用、需要用哪个路径。这能省掉新会话大量的试错。
- **把取代关系写进去。** 审阅时间一长，前后决定难免冲突；新会话最容易在这里出错。
- **要求先复述再动手。** 这是成本最低的一道检查。
